# Agent configuration verification

Before replacing an existing owner, confirm:

## Guidance

- The configuration addresses a repeated need, meaningful risk, or recurring capability.
- Each behavior has one canonical owner at the narrowest correct scope.
- Always-on rules, conditional skills, and detailed references are separated intentionally.
- Existing behavior is preserved or deliberately removed.

## Delivery

- Links resolve and affected harnesses discover the expected instructions and skills.
- Installation succeeds repeatedly, reports collisions, and preserves unmanaged state.
- Removed owners no longer produce duplicate behavior.

## Safety and lineage

- Public material contains only public context and generic examples.
- Runtime state and authentication material remain untracked.
- Retained external material records its source, pin, and permission or license basis.

## Completion

- Relevant syntax checks and behavior tests pass.
- `jj status`, `jj diff`, and the revision stack match the intended ownership.
- Changes remain local until publication is requested or belongs to the established workflow.
